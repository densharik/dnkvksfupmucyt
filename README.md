# tg-funnel

Мини-воронка регистраций на эфир в Telegram и дашборд статистики в виде Telegram Mini App.

```
/start?метка -> приветствие -> "подтвердите, что вы живой человек" (контакт)
             -> "Спасибо"   -> +10 с: программа и кнопки на канал/подарки
                            -> +60 с: билет розыгрыша и личная реферальная ссылка
             -> нет телефона через 2 мин -> один дожим
```

Стек: aiogram 3, FastAPI, PostgreSQL, docker compose. Тексты, тайминги и кнопки лежат в [`config/launch.yaml`](config/launch.yaml): один файл описывает один запуск.

| Пункт ТЗ | Где |
|---|---|
| /start, приветствие, запрос телефона | `app/bot.py` |
| 2 сообщения через 10 с и через 1 мин | `config/launch.yaml`, отправка в `app/worker.py` |
| Тексты и тайминги в YAML | `config/launch.yaml` |
| Миниапп-дашборд | `web/index.html`, данные в `app/stats.py` |

Отсчёт 10 с и 1 мин идёт от момента, когда человек оставил телефон: сообщения получают только зарегистрированные. Сверх ТЗ: источник по метке, номер в розыгрыше за приглашённого друга, один дожим тех, кто не оставил телефон.

## Проверить за 2 минуты

1. `cp .env.example .env`, вписать `BOT_TOKEN` и свой id в `ADMIN_IDS` (id покажет @userinfobot).
2. `docker compose up --build`.
3. Открыть бота по ссылке `https://t.me/<бот>?start=reg_tgc_oldmero_1_2810_ut`, нажать «Старт» и «Поделиться контактом».
4. Дашборд: кнопка меню «Дашборд» в чате с ботом. Без Telegram: `DASHBOARD_DEV=1` в `.env` и http://localhost:8000.

## Запуск

Нужны Docker и токен бота из @BotFather.

```bash
cp .env.example .env        # вписать BOT_TOKEN и свой ADMIN_IDS
docker compose up --build   # Postgres + бот + API + https-туннель
```

В логах появится строка `dashboard: https://xxxx.trycloudflare.com/`. У админа в чате с ботом появится кнопка меню «Дашборд», и есть команда `/dashboard`.

Если туннель Cloudflare не поднимается (в части сетей РФ соединение с ним рвётся), подойдёт любой другой https-туннель: `ssh -R 80:localhost:8000 nokey@localhost.run`, полученный адрес вписать в `WEBAPP_URL` и перезапустить бота.

Демо-данные, чтобы дашборд не был пустым (400 регистраций за 14 дней с метками):

```bash
docker compose exec bot uv run python -m scripts.seed
```

Без Docker для бота: `docker compose up -d db tunnel`, затем `uv run python -m app`. Если в `.env` стоит `DASHBOARD_DEV=1`, дашборд открывается в обычном браузере на http://localhost:8000.

Тесты: `uv run pytest`. Тесты очереди работают на живом Postgres из compose; без базы они пропускаются.

## Метки источников

Формат меток взят из боевых ботов: `reg_<канал>_<аудитория>_<номер поста>_<ДДММ>_<ut|ob|ve>`.

| Ссылка | Что значит |
|---|---|
| `?start=reg_tgc_oldmero_2_2710_ob` | телеграм-канал, база прошлого эфира, 2-й пост за 27.10, обед |
| `?start=reg_Site_Site_1_2010_ob` | лендинг |
| `?start=ref_123456` | пришёл по приглашению пользователя 123456 |
| без параметра | organic |

Источник фиксируется по первому касанию: если человек позже пришёл по другой ссылке, источник не перезаписывается.

## Что показывает дашборд

- Воронка по шагам: старт, телефон, сообщение 1, сообщение 2. На каждом шаге видна конверсия от шага выше и сколько людей потеряно. При выборке меньше 30 человек стоит пометка «мало данных».
- Источники, посты и время поста (утро, обед, вечер): где регистрации реально доходят до телефона.
- Регистрации за 14 дней, рефералы, последние регистрации с маской телефона.
- Очередь сообщений: сколько сообщений ждёт, отправлено, сколько ошибок и сколько людей заблокировали бота. Это первое, куда смотреть в день эфира.

Доступ к API только с подписанным Telegram `initData` и только для id из `ADMIN_IDS`. Подпись проверяется на сервере, потому что в ответе API есть персональные данные.

## Как устроено

```
app/
  __main__.py  один процесс: polling бота + воркер очереди + API + поиск адреса туннеля
  bot.py       хендлеры: /start, контакт, блокировка бота, /dashboard
  worker.py    отправка отложенных сообщений из таблицы jobs
  db.py        схема и запросы (asyncpg, без ORM)
  stats.py     агрегаты для дашборда
  deeplink.py  разбор меток
  initdata.py  проверка подписи Mini App
web/index.html дашборд, без сборки и фреймворков, цвета из темы Telegram
config/launch.yaml
```

Две таблицы: `users` (человек, источник, телефон, билет) и `jobs` (очередь отложенных сообщений).

## Грабли и как они закрыты

| Что может сломаться | Что сделано |
|---|---|
| Бот перезапустили, отложенные сообщения потерялись | Отложенные сообщения хранятся в Postgres, а не в `asyncio.sleep`. После рестарта воркер досылает то, что не успел. Задачи, зависшие в `processing` дольше минуты, возвращаются в очередь. |
| Сообщение ушло дважды | `UNIQUE (tg_id, key)` в `jobs`. Повторный контакт или `/start` не планирует сообщение второй раз, телефон и билет выдаются один раз. |
| Два экземпляра бота отправили одно и то же | Задачи забираются через `FOR UPDATE SKIP LOCKED`. |
| В день эфира всем сразу, ответ Telegram 429 | Между отправками стоит пауза (~20 сообщений/с при лимите 30/с). При `retry_after` задача переносится ровно на столько, сколько попросил Telegram, а не теряется. |
| Пользователь заблокировал бота | Ловим `my_chat_member` и `403`, помечаем `blocked_at`, его остальные сообщения пропускаются. На дашборде это отдельная метрика. |
| Человек прислал чужой контакт | Принимается только контакт с `user_id` самого отправителя. |
| Сетевая ошибка или 5xx | До 3 попыток с паузой 5, 10, 20 с, потом `failed` с текстом ошибки на дашборде. |
| Опечатка в YAML перед эфиром | Конфиг проверяется pydantic при старте. Ошибка конфига валит запуск сразу, а не на первом пользователе. |
| Персональные данные (152-ФЗ) | Согласие с обработкой стоит в описании бота, до /start, и ведёт на политику того, кто хранит данные. Телефон в логи не пишется, на дашборде он маскируется. |

Осознанные компромиссы:

- **Доставка «хотя бы раз».** Если процесс упал ровно между отправкой и записью статуса, сообщение уйдёт повторно. Окно в миллисекунды, а потерять сообщение хуже, чем отправить дубль.
- **Один процесс для бота, воркера и API.** Для локального запуска так проще. В проде их можно разнести, схема очереди это позволяет.

## Как расширить

- **Картинки и видео-кружок.** Добавить в `messages` поле `photo` или `video_note` и отправлять через `send_photo` или `send_video_note`.
- **Засчитывать друга только с подпиской на канал.** Бот должен быть админом канала, тогда хватит проверки `get_chat_member` перед `credit_referrer`.
- **VK и MAX.** Очередь и статистика от мессенджера не зависят: новые хендлеры пишут в те же `users` и `jobs`.
